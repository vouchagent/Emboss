# EmbossSpec Format

Documents are defined using **EmbossSpec**, a declarative JSON-serializable specification. Every element is a typed Python dataclass that can be constructed programmatically, deserialized from JSON, or generated by an LLM via structured output. The spec is the single source of truth: the visual PDF, the PDF/UA structure tree, and the HTML/Markdown/DOCX exports are all derived from it.

```json
{
  "title": "Annual Report",
  "style": "corporate",
  "content": [
    {"type": "heading", "text": "Overview", "level": 1},
    {"type": "paragraph", "text": "Company performance exceeded targets."},
    {"type": "table", "headers": ["Q1", "Q2"], "rows": [["$1M", "$1.2M"]]}
  ]
}
```

`title` and `content` are required; everything else has defaults.

## Document fields

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `title` | string | required | Document title (PDF metadata; required for PDF/UA) |
| `author` | string | `""` | Author name |
| `subject` | string | `""` | Subject line |
| `keywords` | string | `""` | Comma-separated keywords |
| `language` | string | `"en-US"` | BCP 47 language tag |
| `style` | string | `"corporate"` | Preset: `legal`, `finance`, `academic`, `corporate`, `minimal`, `journal`, `brief` |
| `page` | object | letter | Page geometry, see below |
| `content` | array | required | Ordered list of block elements |
| `header_text` / `footer_text` | string | `null` | Simple running header/footer |
| `header` / `footer` | object | `null` | Structured header/footer with `left`/`center`/`right` slots |
| `page_numbers` | bool | `true` | Page numbers in the footer |
| `tagged` | bool | `true` | Generate the PDF/UA structure tree |
| `toc` | bool | `false` | Insert an auto-generated table of contents |
| `legal` | object | `null` | Watermark, Bates numbering, line numbering |
| `smart` | bool | `true` | Content intelligence on the smart parse path |

Header and footer text fields accept `{page}` and `{pages}` placeholders, resolved at render time.

<Callout type="info">
Two Document fields are Python-API only and not part of the LLM JSON schema:
`color_mode` (`"rgb"` or `"cmyk"`, see [Color and Print](/color)) and `pdfa`
(PDF/A-2b conformance). Set them on the `Document` after parsing, or construct
the `Document` directly.
</Callout>

### Style presets

Seven built-in stylesheets encode type scale, leading, table rules, and spacing:

| Preset | Character | Use case |
|--------|-----------|----------|
| `legal` | serif, justified, generous leading | contracts, briefs, pleadings |
| `finance` | sans, tight, tabular | reports, filings, data sheets |
| `academic` | serif body, sans headings, justified | papers, theses |
| `corporate` | sans, readable, roomy | memos, policies, manuals |
| `minimal` | compact, minimal ornament | data exports |
| `journal` | serif, justified, forest accent | journals, periodicals |
| `brief` | executive, bold accents | executive briefs, one-pagers |

### Page geometry

```json
{"page": {"preset": "a4", "margin_left": 108, "columns": 2, "column_gap": 18}}
```

Presets: `letter`, `a4`, `legal`. Explicit `width`/`height` (points, 72 per inch) override the preset. Margins default to 72pt. `columns` accepts 1 through 4; content flows between columns automatically and `column_gap` is in points.

### Legal features

```json
{"legal": {
  "watermark": "CONFIDENTIAL",
  "watermark_opacity": 0.12,
  "line_numbering": true,
  "bates_prefix": "ACME-",
  "bates_start": 1,
  "bates_digits": 6,
  "bates_position": "bottom-right"
}}
```

## Block types

Every content block carries a required `type` discriminator. The canonical tags are: `heading`, `paragraph`, `table`, `bullets`, `numbered`, `image`, `chart`, `footnote`, `callout`, `code_block`, `math`, `bibliography`, `svg`, `page_break`, `rule`. Synonym tags (`bullet_list`, `numbered_list`, `math_block`, `horizontal_rule`) are normalized during parsing.

### heading

```json
{"type": "heading", "text": "Executive Summary", "level": 1}
```

Levels 1 through 6. Level drives both the visual size and the `/H1`..`/H6` structure tag. Optional `numbering` adds a section-number prefix such as `"3.2"`.

### paragraph

```json
{"type": "paragraph", "text": "Plain text paragraph."}
```

For inline formatting use `runs` instead of `text`:

```json
{"type": "paragraph", "runs": [
  {"text": "Revenue increased "},
  {"text": "12%", "bold": true, "color": "0d6e3f"},
  {"text": " year over year.", "italic": true}
]}
```

Run fields: `text` (required), `bold`, `italic`, `font_size`, `font_family`, `color` (6-digit hex, no `#`), `link` (URL).

### table

```json
{
  "type": "table",
  "headers": ["Region", "Q3 Revenue", "Change"],
  "rows": [
    ["North America", "$2,431,000", "+11.5%"],
    ["Europe", "$1,204,300", "+4.7%"]
  ],
  "caption": "Revenue by region",
  "stripe": true
}
```

Cells are strings, or objects for formatting: `{"value": "$1,234.56", "align": "decimal"}` aligns numbers on the decimal point; cell objects also accept `bold` and `background`. Other fields: `column_widths` (relative, auto-computed if omitted) and `repeat_header` (default `true`, repeats the header row when a table splits across pages). Columns that are at least 70% numeric get decimal alignment automatically.

### bullets

```json
{"type": "bullets", "items": ["First item", "Second item"]}
```

### numbered

```json
{"type": "numbered", "items": ["Step one", "Step two"], "start": 1}
```

### image

```json
{"type": "image", "source": "chart.png", "width": 400,
 "caption": "Figure caption", "alt_text": "Description for accessibility"}
```

JPEG or PNG. `width`/`height` in points; `align` is `left`, `center` (default), or `right`.

### chart

```json
{"type": "chart", "chart_type": "bar",
 "labels": ["Q1", "Q2", "Q3", "Q4"], "values": [100, 150, 130, 180],
 "title": "Quarterly Revenue"}
```

Types: `bar`, `line`, `pie`, `scatter`. Multi-series charts use `series` instead of `values`:

```json
{"type": "chart", "chart_type": "scatter", "labels": ["Q1", "Q2"],
 "series": [
   {"label": "North", "values": [100, 150]},
   {"label": "South", "values": [90, 120]}
 ],
 "x_title": "Quarter", "y_title": "Units", "legend": true}
```

Pie charts use the first series only. Charts render as native vector graphics.

### footnote

```json
{"type": "footnote", "text": "Source: Annual Report 2024", "marker": "1"}
```

### callout

```json
{"type": "callout", "text": "This action cannot be undone.",
 "variant": "warning", "title": "Warning"}
```

Variants: `info` (blue), `warning` (amber), `success` (green), `danger` (red), `note` (gray).

### code_block

```json
{"type": "code_block", "code": "def hello():\n    print('hi')",
 "language": "python", "line_numbers": true}
```

Optional: `theme` (`dark_modern`, `light_clean`, `night_owl`), `start_line`, `highlight_lines`, `caption`.

### math

```json
{"type": "math", "source": "E = mc^{2}", "display": true}
```

LaTeX-subset source; see [Math Notation](/math).

### bibliography

```json
{"type": "bibliography", "bib_style": "ieee", "citations": [
  {"key": "ref1", "authors": ["A. Author"], "title": "A Paper", "year": 2024}
]}
```

Citation fields: `key` (required), `authors`, `title`, `year`, `journal`, `volume`, `pages`, `publisher`, `doi`, `url`, `entry_type` (`article`, `book`, `inproceedings`, `misc`). Styles: `ieee`, `apa`, `numbered`.

### svg

```json
{"type": "svg", "source": "<svg width=\"200\" height=\"100\">...</svg>",
 "width": 200, "height": 100, "alt_text": "Diagram"}
```

Rendered as native PDF paths, no rasterization. Supported elements: `rect`, `circle`, `ellipse`, `line`, `polygon`, `polyline`, `path`.

### page_break and rule

```json
{"type": "page_break"}
{"type": "rule", "thickness": 0.5, "color": "cccccc"}
```

## Per-element style overrides

Most blocks accept a `style` object that overrides the preset for that element only:

```json
{"type": "paragraph", "text": "Fine print.",
 "style": {"font_size": 8.0, "color": "6b7280", "align": "justify"}}
```

Fields: `font_family`, `font_size`, `bold`, `italic`, `color`, `align`, `line_height`, `space_before`, `space_after`, `indent_first`.

<Callout type="info">
The Python API has one block with no JSON tag: `BlockQuote` (a quoted
passage with optional attribution, tagged `/BlockQuote`). It is produced by
the Markdown parser and available as a dataclass, but is not part of the
LLM JSON vocabulary.
</Callout>
